# J1：混合输入联调与现场验收

负责人：A、B 共同。A 组装正式游戏，B 接入控制器并调参。状态：待实施。

## 1. 目标与交付范围

证明两个模块在同一页面中按公共合同协作，先完成一次混合输入投掷，再完成整局、双模式和现场展示。基线是**手套选球与实时预览＋键鼠锁定/发射/取消**；完整手套确认是分开验收的可选部分。

本卡验证真实实现，不把独立模拟 host 或八球示例当作正式游戏。依据：[手册](../Flock-and-Flick-开发手册-v2.0.md)第 16–18 节及 [固定样例](../interface-v1.1/fixtures.json)。

## 2. 接线与文件归属

- A 修改 `src/main.ts`、正式 Scene 与 host 组装；移除旧验证页的常驻相机/Worker 实例。
- B 修改 `src/motion/controller.ts` 及体感内部模块；向 A 提供公开入口，不直接修改游戏库存或 Scene。
- 调试记录放在本目录的 `records/J1-日期.md`（新增）；使用 [验收记录模板](验收记录模板.md)。
- 调试用人工阶段开关或模拟命令不能作为正式玩家页面的默认入口；需要保留时放独立调试页。

组装顺序：创建游戏状态/host → 创建控制器 → setContext 初始上下文 → 用户点击后 start → 完成所需玩家校准 → 游戏允许进入 select。状态变更先通知控制器再返回回执，单纯预览变化不重置动作计时。离开体验、重开控制器或页面退出时有唯一清理路径。

## 3. 分三次收口

| 节点 | 最低输入 | 本次必须证明 | 暂不作为阻塞项 |
| --- | --- | --- | --- |
| J1-P1 首次投掷 | A1、A2 普通球、A3 最小界面；B1/B2/B3 默认动作 | 选球、实时预览、键鼠锁/发/取消、掉线恢复；五次完整投掷 | 五关、美术、声音、可选体感确认 |
| J1-P2 完整游戏 | A2 排斥球、A4 双模式；B 双人档案 | 单人流程与键鼠整局；两场手套＋键鼠确认的双人比赛 | 尚未启用的可选动作 |
| J1-P3 展示验收 | 同一构建版本、目标机器、实际相机/手套/光照 | 手册第 17 节的全部必需验收，构建版启动和现场记录 | 关闭且明确标注未交付的可选动作 |

P1 的“五次完整投掷”可跨单人重试完成，不要求一局拥有五球。某阶段通过后保留版本；后续更改影响既有路径时补相关回归，同一构建已有可靠记录可复用。

## 4. 第一轮必须共同检查

| 编号 | 操作 | 可观察结果 |
| --- | --- | --- |
| J1-01 | 手套选球，转动/拉开双手，尚未锁定 | 角度、力度、箭头和预计路径实时改变；不出现等待稳定后才显示的延迟 |
| J1-02 | Enter 锁定，再移动手套；Esc 取消；再次锁定后 Space 发射 | 锁定值保持，取消恢复实时预览；真实球按冻结参数发射且只扣一份库存 |
| J1-03 | motion 预览时使用键鼠选球/取消；移动鼠标与显式接管分别试验 | 合法阶段键鼠可用；鼠标移动不抢占，方向键/滚轮/接管按钮按合同切源 |
| J1-04 | armed 中遮住任意手套；继续遮挡并用键鼠重新锁定/发射 | 第一次失效解锁且不误发射；持续无效不反复撤销键鼠确认 |
| J1-05 | 在 adjust 注入 FIRE、换玩家后注入旧 context 请求、注入带新 id 的过期命令 | 正确拒绝，无库存或实体副作用；不能将合法重复回执误当过期命令处理 |
| J1-06 | 重发同一有效 FIRE；调试端让键鼠和已启用的体感动作持同一旧 context 竞争 | 重放返回缓存；竞争仅一条生效，只出现一球，不重复扣库存 |
| J1-07 | resolving 中关相机或触发 Worker 超时；稳定后恢复 | 运动与效果继续；键鼠可继续游戏；恢复需重新就绪，不自动发射 |
| J1-08 | 重试、回菜单、重新开启手套、切换玩家 | 新身份正确；旧帧/旧回执/旧手势不影响新局，只有一套媒体和 Worker 实例 |

## 6. 性能与调参记录

记录具体机器、浏览器、提交/文件版本、分辨率、识别频率、光照、站位与参数版本。性能在正式场景、实际摄像头运行中测量，不能使用八球合成图结果代替。

输入延迟目标为采样到画面更新中位数≤150ms、P95≤250ms，不包括人为停留时间。保留可统计的时间戳记录：采样时间、结果到达、命令接受、下一次绘制。Worker 时钟仅计算自身 processingMs；跨线程以原样传回的主线程采样时间为准。若用录像测量实体动作到屏幕响应，单独说明口径。

一次优先调整一个参数组，区分游戏错误与识别错误。键鼠也异常先查 A；只有手套输入异常先查 B。调整后复查受影响的验收，不能把降低有效性要求当作减少误触的办法。

## 7. 构建与交付

在工程根目录执行：

```powershell
npm.cmd run check:vendor
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

在 `http://127.0.0.1:4173/` 完成关键混合投掷及停止/重开检查。现场展示前确认依赖和资源在本地，断开外网复查；仍需保持本地服务。退出时先停止视觉再关闭服务。

所有必需项都有实际通过证据才标“全部验收完成”。真实设备、手套或目标机器不在场时，可以交付代码并标“现场验收待确认”，列出未测编号。可选动作分别标通过/关闭/待验证，不得把关闭写成通过。
